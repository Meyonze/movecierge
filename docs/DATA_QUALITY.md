# 自治体データの品質管理

`data/city_data.json` は利用者に表示するデータ、`data/city_data_review.json` は公開前に人が確認する候補データです。自治体IDは `data/cities.json` を正とします。

## 現在の監査結果

`node scripts/validate-data.mjs` の確認対象は、全国1,740自治体、本データ1,441件、レビュー用データ436件です。

- 本データには `confidence: high` が944件、信頼度未設定が497件あります。
- 本データのうち1件は、転出・転入の公式案内URLのどちらかが未収録です。画面上では公式サイト検索へフォールバックしますが、優先して補完します。
- レビュー用データには、未完成の候補（窓口情報や `hasData` がないもの）が含まれます。これは公開用データに混ぜません。
- 245件は本データの `high` とレビュー用の `low` が競合しています。本データを表示に使い、レビュー側の補足情報は公式サイトで再確認してから個別に反映します。
- 63件は本データの `high` と、信頼度が未設定のレビュー候補が重複しています。これは「低信頼度との競合」ではないため、別枠で確認します。

この数値はデータ更新時に変わるため、実際の作業では検証スクリプトの出力を正とします。

自治体ごとの確認リストが必要な場合は、`node scripts/validate-data.mjs --json` を実行します。標準出力のJSONには、警告の種類ごとに自治体ID・自治体名・都道府県・公開データとレビュー用データの信頼度が含まれます。

## 更新手順

1. `zenkoku_hikkoshi_research.py` の結果は、まずレビュー用データとして扱う。
2. 転出・転入の公式URL、窓口説明、対象自治体IDを確認する。
3. 確認できたものだけを `data/city_data.json` に反映し、`confidence` を `high` にする。
4. `node scripts/validate-data.mjs` を実行し、構造エラーがないことを確認する。
5. URL不足・信頼度未設定・競合の警告を確認してからPRを作る。

## 優先順位

1. 本データでURLが不足している1件
2. `high` と `low` が競合する245件
3. 本データの `high` と信頼度未設定レビュー候補が重複する63件
4. 本データの信頼度未設定497件
5. レビュー用データの未完成候補

URLの存在だけで内容の正しさは保証されません。自治体の公式サイト上で、転出・転入の対象手続きと窓口が一致することを確認します。
